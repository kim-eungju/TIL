## Item 34. int 상수 대신 열거 타입을 사용하라

왜 `int`상수를 쓰면 안 될까?
예전 Java에는 `enum`이 없어서 이렇게 작성함
```java
public class OrderStatus {
    public static final int READY = 0;
    public static final int SHIPPING = 1;
    public static final int COMPLETE = 2;
}
```
둘 다 int라서 컴파일된다
하지만 상태(Status)와 권한(Role)은 완전히 다른 개념이다
```java
changeStatus(OrderStatus.READY);
changeStatus(UserRole.ADMIN); // 컴파일 성공
```
`enum`이라면?
```java
enum OrderStatus {
    READY,
    SHIPPING,
    COMPLETE
}

enum UserRole {
    ADMIN,
    USER
}
```
```java
void changeStatus(OrderStatus status)
```
이제 컴파일 에러가 발생하고 안전하다
```java
changeStatus(UserRole.ADMIN); // 컴파일 에러
```
> `int`나 `String`상수 대신 `enum`을 사용하라 `enum`은 타입 안정성을 제공한다.

## Item 35. ordinal 메서드 대신 인스턴스 필드를 사용하라

`enum`에는 기본적으로 `ordinal()`이라는 메서드가 있다
결론부터 얘기하면 이 메서드를 쓰지 않으면 된다
```java
public enum OrderStatus {
    READY,
    SHIPPING,
    COMPLETE
}
```
몇 번째가 선언되었는지를 알려주는 메서드다
```java
System.out.println(OrderStatus.READY.ordinal());      // 0
System.out.println(OrderStatus.SHIPPING.ordinal());  // 1
System.out.println(OrderStatus.COMPLETE.ordinal());  // 2
```
DB에 이런식으로 저장하며 사용중 
```
0 = READY
1 = SHIPPING
2 = COMPLETE
```
`PAYMENT`상태라도 추가되면?
모든 데이터가 깨진다
```java
public enum OrderStatus {
    READY, // 1
    // PAYMENT, 추가
    SHIPPING // 2
    COMPLETE // 3
}
```
상태 코드가 필요하면 필드를 직접 만들어서 사용하자
```java
public enum OrderStatus {

    READY(1),
    SHIPPING(2),
    COMPLETE(3);

    private final int code;

    OrderStatus(int code) {
        this.code = code;
    }

    public int getCode() {
        return code;
    }
}
```
> `ordinal()`은 지금까지도 사용한 적이 없지만 앞으로도 사용하지 말자

## Item 36. 여러 개의 enum 값을 동시에 저장해야 한다면 비트 연산 대신 EnumSet을 사용하라

비트 필드는 생략하고, `EnumSet`만 설명하겠다
`EnumSet`은 `Set`의 한 종류다
```
Set (인터페이스)
   ↑
AbstractSet
   ↑
EnumSet
```
즉, `Set`을 써도 되고, `EnumSet`을 써도된다.
```java
Set<Role> roles = new HashSet<>();
```
```java
Set<Role> roles = EnumSet.of(Role.USER);
```
하지만 저장 대상이 `enum`뿐일때는 `EnumSet`을 쓰면 된다
그 이유는
- 중복이 없고
- 성능도 더 좋고
- 메모리도 적게 쓰기 때문

> 실무에서 `Enum`만 저장해야되는 상황에서 아래 처럼 `Set<Role>`인터페이스 타입으로 선언하고, 실제 구현체는 `EnumSet`을 사용해보자

```java
Set<Role> roles = EnumSet.of(Role.USER, Role.ADMIN);
```

## Item 37. ordinal 인덱싱 대신 EnumMap을 사용하라

`ordinal` 인덱싱은 생략하고, `EnumMap` 예제만 설명하겠다

```java
public enum AssetType {
    OS,
    DB,
    WEB
}
```
```java
public class Asset {

    private final String name;
    private final AssetType type;

    public Asset(String name, AssetType type) {
        this.name = name;
        this.type = type;
    }

    public AssetType getType() {
        return type;
    }
}
```
```java
public interface AssetValidator {
    AssetType supportType();
    void validate(Asset asset);
}
```
```java
@Component
public class OsAssetValidator implements AssetValidator {

    @Override
    public AssetType supportType() {
        return AssetType.OS;
    }

    @Override
    public void validate(Asset asset) {
        System.out.println("OS 검증");
    }
}
```
```java
@Service
public class AssetValidationService {

    private final EnumMap<AssetType, AssetValidator> validators;

    public AssetValidationService(List<AssetValidator> validatorList) {

        validators = new EnumMap<>(AssetType.class);

        for (AssetValidator validator : validatorList) {
            validators.put(validator.supportType(), validator);
        }
    }

    public void validate(Asset asset) {

        AssetValidator validator = validators.get(asset.getType());

        if (validator == null) {
            throw new IllegalArgumentException("지원하지 않는 자산 타입");
        }

        validator.validate(asset);
    }
}
```
사용
```java
Asset asset = new Asset("WINDOWS_PC", AssetType.OS);
assetValidationService.validate(asset);
```
> `EnumMap`을 사용해서 `enum`자체를 키로 조회하는 서비스를 개발하게되면, 위 코드의 패턴을 기억하자

## Item 38. 확장할 수 있는 열거 타입이 필요하면 인터페이스를 사용하라

예를 들어 계산기를 만든다고 가정
```java
public enum Operation {
    PLUS, MINUS
}
```
시간이 지나서 새로운 연산을 추가하고 싶어지면?
```java
TIMES
MOD 
...
```
`enum`은 이미 `java.lang.Enum`을 상속하고 있고, Java는 다중 상속을 지원하지 않기때문에 상속은 불가능하다.

인터페이스를 사용하자
```java
private static <T extends Enum<T> & Operation>
void test(Class<T> opEnumType, double x, double y) {

    for (Operation op : opEnumType.getEnumConstants()) {
        System.out.println(op.apply(x, y));
    }
}
```
T는 `enum`이어야하며, `BasicOperation`도 되고, `ExtendedOperation`도 된다.

> `enum` 자체는 상속으로 확장할 수 없으므로, 공통 인터페이스를 정의하고 여러 `enum`이 이를 구현하게 만들어 같은 타입처럼 다뤄보자

## Item 39. 명명 패턴보다 애너테이션을 사용하라

명명 패턴이란?
Java 5 이전에는 애너테이션이 없었고, 프레임워크는 메서드 이름으로 의미를 표현했다.
```java
public class SampleTest {

    public void testLogin() {
    }

    public void testSignup() {
    }
}
```
프레임워크는 "이름이 test로 시작하면 테스트 메서드다." 라고 판단한다.

정확한 표현으로 애너테이션을 사용하자

```java
@Test
public void loginTest() {

}
```

> 코드에 특별한 의미를 전달하려고 이름으로 약속하지 말고, 애너테이션으로 명시하라

## Item 40. @Override 애너테이션을 일관되게 사용하라 

재정의(override)하려는 메서드에는 항상 `@Override`를 붙여라

```java
class Child extends Parent {

    @Override
    public void print(Object obj) {
        System.out.println(obj);
    }
}
```
> 실수로 오버로드가 되지 않도록 재정의하는 모든 메서드에는 항상 `@Override`를 붙이자

## Item 41. 정의하려는 것이 타입이라면 마커 인터페이스를 사용하라

마커란? 아무 기능도 없지만 이 객체는 이런 특징을 가진다고 표시하는 것

```java
public interface Serializable {
}
```
```java
public class User implements Serializable {
}
```
메서드는 하나도 없지만 이 객체는 직렬화 할수 있는 객체라고 표시한다

```java
@MySerializable
class User {
}
```
애너테이션도 표시 아닌가? 라고 생각할 수 있다 그러나 인터페이스를 사용하면 아래와 같은 장점을 누릴 수 있다.

- 타입이 생긴다
- 컴파일 단계에서 오류 발견
- 적용 대상을 제한할 수 있다

> 표시하려는 것이 '객체의 종류(타입)'라면 마커 인터페이스를, 단순히 프레임워크나 도구에 전달할 메타데이터라면 마커 애너테이션을 사용하라.
