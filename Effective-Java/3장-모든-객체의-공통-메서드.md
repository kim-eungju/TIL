## Item 10-12. equals, hashCode, toString 재정의
### equals

재정의하지 않는 경우 (값은 같아도 객체 주소가 다른것으로 판단)

```java
new MacAddress("AA").equals(new MacAddress("AA")); // false
```

우리가 원하는건?
```java
MacAddress a = new MacAddress("AA-BB");
MacAddress b = new MacAddress("AA-BB");

a.equals(b); // true 로 기대함
```

### hashCode
`equals`와 반드시 함께 재정의 해야한다
이유는 `HashMap`과 `HashSet`때문이다
재정의 하지 않으면 값이 2가 나올 수 있다

```java
Set<MacAddress> set = new HashSet<>();

set.add(new MacAddress("AA"));
set.add(new MacAddress("AA"));

System.out.println(set.size());
```

### toString
재정의하지 않으면?
```java
log.warn("invalid asset row. asset={}", asset);
// invalid asset row. asset=com.example.AssetLogical@ab123
```
이런식으로 재정의 하면 디버깅에 좋다.
다만, 비밀번호 같은 민감정보는 조심하자
```java
@Override
public String toString() {
    return "MacAddress[value=" + value + "]";
}
```
### record
`equals`, `hashCode`, `toString` 재정의를 한번에 해결해준다. (VO랑 잘 맞음)
```java
public record MacAddress(String value) { 
}
```
```java
MacAddress a = new MacAddress("AA");
MacAddress b = new MacAddress("AA");

System.out.println(a.equals(b)); // true
System.out.println(a.hashCode() == b.hashCode()); // true
System.out.println(a); // MacAddress[value=AA]
```

즉, 아래처럼 직접 안만들어도 됨
```java
@Override equals
@Override hashCode
@Override toString
```

> "객체의 정체성(메모리 주소)"이 아니라 "객체의 값"으로 동일성을 판단하기 위해서는 `equals`와 `hashCode`를 함께 재정의하자 이를 쉽게 하려면 `record`클래스를 사용하자

## Item 13. clone재정의는 주의해서 진행하라

결론부터 얘기하면 clone을 쓰지 말고 복사 생성자를 사용하라.

이유
- 생성자를 호출하지 않는다.
- 얕은 복사가 기본이다.
- Cloneable 설계가 이상하다.
- 예외 처리도 필요하다.
- 구현이 어렵다.

복사 생성자
```java
public class User {

    private String name;
    private int age;

    public User(User other) {
        this.name = other.name;
        this.age = other.age;
    }
}
```
```java
User user2 =
    new User(user1);
```

## Item 14. Comparable을 구현할지 고려하라

`Comparable`이란? 
숫자나 문자를 아래처럼 정렬한다.
```
Apple
Banana
Orange
```
`Collections.sort(list)`는 `Comparable`인터페이스를 구현하고 있기 때문에 호출하면 자동으로 정렬한다.
```java
Integer implements Comparable<Integer>
String implements Comparable<String>
```

실무에서는 대부분 `Comparator`를 사용한다.
```java
users.sort(
    Comparator.comparing(User::getName)
);
```
`Comparable`을 사용하지는 않는다.
```java
implements Comparable
```
> - `Comparable`는 클래스 내부에서 기본 정렬 기준을 정의한다.
> - `Comparator`는 클래스 외부에서 상황에 맞는 다양한 정렬 기준을 정의한다.
> - 실무에서는 `Comparator`를 더 자주 사용하지만, `LocalDate`, `String`, `Integer`처럼 누구나 동의하는 자연스러운 순서가 있는 타입은 `Comparable`을 구현하는 것이 적합하다.
