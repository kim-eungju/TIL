## Item 85. 자바 직렬화의 대안을 찾으라

자바 직렬화란? 객체를 바이트로 변환해 저장하거나 전송하고, 다시 객체로 복원하는 기능

```java
public class User implements Serializable {
    private String name;
    private int age;
}
```

왜 사용하지 말라는 걸까?
- 보안 문제 : 신뢰할 수 없는 바이트 데이터를 `ObjectInputStream` 으로 읽으면, 예상하지 못한 코드가 실행
- 클래스 구조 변경에 취약 : 필드를 추가하거나 타입을 변경하면 과거에 저장한 데이터를 읽지 못할 수 있음
- 자바에 종속 : 자바 직렬화 데이터는 다른 언어에서 다루기 어렵고, 사람이 내용을 확인하기도 어렵다

그런데, __어차피 그동안 사용할 일이 없었다__

현대는 Jackson, Hibernate, Redis 클라이언트 등이 변환을 처리하므로 `ObjectOutputStream` 을 직접 만질 필요가 없음

> 자바 직렬화는 과거에 객체를 파일,세션,네트워크,캐시에 '그대로' 옮기려고 사용했지만, 지금은 JSON,DB,Protobuf 같은 명시적인 데이터 포맷으로 거의 대체되었다

---

## Item 86. Serializable을 구현할지는 신중히 결정하자

- 버전 호환성 문제가 생긴다. `serialVersionUID` 등을 신경 써야 한다.
- 보안 위험이 생길 수 있다. 신뢰할 수 없는 데이터를 역직렬화하는 것은 특히 위험하다.
- 상속 구조에도 영향을 준다. 부모가 `Serializable` 이면 자식도 직렬화 대상이 된다.

```java
public class BindParams extends HashMap<String, String> {

    @Serial
    private static final long serialVersionUID = 1L;
}
```

> 정말 필요한 경우가 아니라면 Serializable을 구현하지 말고, 구현한다면 장기적인 호환성과 보안까지 고려하자

## Item 87. 커스텀 직렬화 형태를 고려해보라

저장할 데이터의 논리적 형태를 따로 설계하자

```java
public class User implements Serializable {

    private String name;
    private String password;

    private void writeObject(ObjectOutputStream out) throws IOException {
        // 직렬화할 데이터만 직접 결정
        out.writeObject(name);
    }

    private void readObject(ObjectInputStream in)
            throws IOException, ClassNotFoundException {
        // 정해둔 직렬화 형태에 맞춰 복원
        name = (String) in.readObject();
    }
}
```

> 기본 직렬화(Serializable)에 객체 구조를 그대로 맡기지 말고, 필요하면 직렬화 형태를 직접 설계하자

## Item 89. 인스턴스 수를 통제해야 한다면 readResolve보다는 열거 타입을 사용하라

readResolve 는? 

역직렬화로 객체가 만들어진 뒤, 그 객체 대신 `readResolve()`가 반환한 객체를 최종 결과로 사용하게 하는 메서드

싱글턴처럼 인스턴스가 하나여야 한다면 `readResolve()` 대신 `enum`을 쓰자

```java
public enum Elvis {
    INSTANCE;
}
```

> `Serializable` 싱글턴은 역직렬화하면 새 인스턴스가 생길 위험이 있는데, `enum`은 JVM이 인스턴스가 하나임을 보장해준다

## Item 90. 직렬화 프록시 사용을 검토하라

이렇게 하면 역직렬화할 때 __프록시 데이터 → 정상 생성자__ 를 통해 객체 생성이 가능해서 불변식이 깨질 위험을 줄일 수 있다

```java
class User implements Serializable {
    private String name;
    private int age;

    private Object writeReplace() {
        return new SerializationProxy(this);
    }

    private static class SerializationProxy implements Serializable {
        private final String name;
        private final int age;

        SerializationProxy(User user) {
            this.name = user.name;
            this.age = user.age;
        }

        private Object readResolve() {
            return new User(name, age);
        }
    }
}
```

> 객체 자체를 직렬화하지 말고, 직렬화 전용 프록시 객체를 만들어 대신 저장하자
