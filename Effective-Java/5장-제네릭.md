## Item 26. Raw Type(로 타입)을 사용하지 말라

Raw Type(로 타입)
```java
List list = new ArrayList();
```
아무거나 들어간다.
```java
List list = new ArrayList();

list.add("hello");
list.add(123);
```
컴파일단에서 이런 에러를 막을 수 없다.
```java
String s = (String) list.get(1); // ClassCastException
```
`List<Object>`와는 다르다. `List`는 "제네릭 타입 체크 자체를 포기한다."

> 지금까지 저렇게 쓴적도 없지만 앞으로도 저렇게 쓰지말자

---

## Item 27. 비검사(Unchecked) 경고를 제거하라

컴파일은 되는데 `Unchecked assignment`이런 경고가 나온다. 이 경고를 최대한 지우는게 이번 아이템의 핵심이다.

```java
List<String> list = new ArrayList(); // Raw Type
```

이렇게 사용하자
```java
List<String> list = new ArrayList<>();
```

> Java에서는 "오른쪽이 Raw Type이면 무조건 `unchecked` 경고" 라는 규칙을 적용했으니, 굳이 경고표시를 띄우지말자

---

## Item 28. 배열보다는 리스트를 사용하라

`배열`은 공변(Covariant)이고, `List`는 불공변(Invariant)이다.
그래서 `List`는 컴파일 타임에 훨씬 안전하다.

```java
String[] strings = new String[3];
Object[] objects = strings;   // 가능 
// 실행하면 ArrayStoreException
```
```java
List<String> strings = new ArrayList<>();
List<Object> objects = strings; // 컴파일 에러
```

> 잘못된 코드를 컴파일 단계에서 막아준다. 이게 제네릭의 가장 큰 장점이다.

---

## Item 29. 이왕이면 제네릭 타입으로 만들라

`Object`를 사용하는 클래스를 만들지 말고 Generic 클래스를 만들어라.

```java
public class Stack {

    private Object[] elements;
    
    public void push(Object e) {
        ...
    }

    public Object pop() {
        ...
    }
}
```
```java
Stack stack = new Stack();
stack.push("ABC");
String s = (String) stack.pop();
```
매번 캐스팅 해야되고, 숫자 잘못 `push` 하면 `ClassCastException` 발생

```java
public class Stack<E> {

    private E[] elements;

    public void push(E e) {
    }

    public E pop() {
    }
}
```
```java
Stack<String> stack = new Stack<>();
stack.push("ABC");
String s = stack.pop();
```
캐스팅이 없고, 컴파일러가 타입을 보장한다.

> "이 클래스는 타입만 다르고 로직은 똑같은데?" 제네릭을 사용하자

## Item 30. 이왕이면 제네릭 메서드로 만들라
유틸성 기능이나 공통 기능은 클래스보다 메서드에 제네릭을 붙이는 것이 더 좋다

```java
// 클래스 전체를 제네릭으로 만든 경우
public class CollectionUtils<T> {

    public T first(List<T> list) {
        return list.get(0);
    }
}
```
```java
// 매번 객체를 만들고 타입을 지정해야함
CollectionUtils<User> userUtils = new CollectionUtils<>();
User user = userUtils.first(users);

CollectionUtils<Order> orderUtils = new CollectionUtils<>();
Order order = orderUtils.first(orders);
```
메서드만 제네릭으로 만들면?
```java
public class CollectionUtils {

    public static <T> T first(List<T> list) {
        return list.get(0);
    }
}
```
```java
// 컴파일러가 알아서 T = User 또는 T = Order 추론한다.
User user = CollectionUtils.first(users);
Order order = CollectionUtils.first(orders);
Product product = CollectionUtils.first(products);
```
> 객체가 타입을 계속 들고 있어야 하면 클래스 제네릭을, 호출할 때마다 타입이 달라지는 공통 기능이라면 제네릭 메서드를 사용하라.

## Item 31. 한정적 와일드카드를 사용해 API 유연성을 높이라

PECS(Producer Extends, Consumer Super) 에 대한 설명이다.

`extends` 데이터를 읽기만 할 때

```java
public void printUsers(List<? extends User> users) {
    for (User user : users) {
        System.out.println(user.getName());
    }

}
```

```java
// 모두 가능
User
AdminUser
GuestUser
```

`super` 데이터를 넣는 경우

```java
public void addUsers(List<? super User> result) {
    User user1 = userRepository.findById(1L);
    User user2 = userRepository.findById(2L);

    result.add(user1);
    result.add(user2);
}
```
```java
// 모두 가능
List<User>
List<Object>
```
> 재사용 가능한 공통 API나 라이브러리를 만들 때 
`? extends`와 `? super`를 고려하라

## Item 32. 제네릭과 가변인수를 함께 쓸 때는 신중하라

가변인수란?
```java
public static void print(String... names) {
	// String... names 는
    // new String[] {"kim", "lee", "park"} 와 같다.
    for (String name : names) {
        System.out.println(name);
    }
}
```

가변인수에 제네릭을 넣어보자
```java
public static <T> T[] getArray(T... values) {
	// String[] arr = getArray("A", "B");
    return values;
}
```
여기까지는 이상없지만, 다른사람이 이 메서드를 잘못 건드리면?
```java
public static <T> T[] getArray(T... values) {
    Object[] obj = values;
    obj[0] = 100;      // Integer 넣기
    return values;
}
```
컴파일은 되지만 실행하면 `Exception`이 발생, `String`만 있을 줄 알았는데 `Integer`가 들어있다. 이걸 `힙 오염(Heap Pollution)` 이라고 한다.

안전한 메서드 예제
```java
@SafeVarargs
public static <T> void print(T... values) {
    for (T value : values) {
        System.out.println(value);
    }
}
```
배열을 수정하지 않고, 밖으로 반환하지도 않는다. 읽기만 하기 때문에 안전하다. 
참고로 `@SafeVarargs`는 "이 메서드는 제네릭 가변인수`(T...)`를 사용하지만, 안전하니까 경고를 하지말라는 의미의 어노테이션이다.

> 제네릭 가변인수`(T...)`는 정말 필요한 경우에만 사용하고, 사용할 때는 배열을 읽기 전용으로만 다뤄라.

## Item 33. 타입 안전 이종 컨테이너를 고려하라

실무 예제
```java
Map<String, Object> data = new HashMap<>();

data.put("name", "Kim");
data.put("age", 30);
data.put("user", new User());
```
꺼낼 때는?
컴파일은 되지만 안에 뭐가 들어있는지 모른다.
```java
String name = (String) data.get("name");
Integer age = (Integer) data.get("age");
```

그래서 등장하는 것이 `타입 토큰`이다.
```java
String.class
Integer.class
User.class
```

제네릭을 이용하면?
```java
public class Favorites {

    private Map<Class<?>, Object> favorites = new HashMap<>();

    public <T> void put(Class<T> type, T value) {
        favorites.put(type, value);
    }

    public <T> T get(Class<T> type) {
        return type.cast(favorites.get(type));
    }
}
```
사실 실무에서 Favorites 와 같은 클래스를 직접 만들일은 거의 없다. (이미 프레임워크 곳곳에서 사용된다.)
ex) `EntityManager.find(User.class, id)`, `ApplicationContext.getBean(UserService.class)` 등등

```java
String name = favorites.get(String.class);
Integer age = favorites.get(Integer.class);
User user = favorites.get(User.class);
```
캐스팅이 없고, 컴파일러가 알아서 타입을 맞춰준다.

> `Object`를 반환해서 캐스팅하지 말고,
`Class<T>`를 받아서 `T`를 반환하는 API를 만들자.
