## 1. 좋은 SQL의 기준 

좋은 SQL이란
> 적은 데이터를 읽고, 적은 작업으로 원하는 결과를 얻는 SQL

즉,
- 읽는 데이터 최소화
- 인덱스 활용
- 불필요한 정렬 제거
- 불필요한 JOIN 제거

---

## 2. SELECT * 사용 지양 

나쁜 예
```sql
SELECT *
FROM user;
```
모든 컬럼을 읽는다.

좋은 예
```sql
SELECT id, name
FROM user;
```
필요한 컬럼만 조회한다.

장점
- 네트워크 사용량 감소
- 메모리 사용량 감소
- Covering Index 가능성 증가

---

## 3. WHERE 조건 작성 

인덱스를 타도록 작성해야 한다.

좋은 예
```sql
WHERE created_at >= '2026-01-01'
```
나쁜 예
```sql
WHERE YEAR(created_at) = 2026
```
함수를 사용하면 인덱스를 활용하기 어렵다.

---

## 4. LIKE 사용 

좋은 예
```sql
LIKE 'kim%'
```
→ 인덱스 사용 가능

나쁜 예
```sql
LIKE '%kim'
```
→ Full Table Scan 가능성이 높다.

---

## 5. OR보다 UNION 고려 

나쁜 예
```sql
WHERE name='Kim'
OR age=20
```
좋은 예
```sql
SELECT ...
WHERE name='Kim'

UNION ALL

SELECT ...
WHERE age=20
```
상황에 따라 인덱스를 더 잘 활용할 수 있다.

---

## 6. EXISTS vs IN 

EXISTS
```sql
WHERE EXISTS (...)
```
IN
```sql
WHERE id IN (...)
```
대량 데이터에서는
__EXISTS가 더 효율적인 경우가 많다.__
(단, MySQL 8.0에서는 옵티마이저가 둘을 비슷하게 최적화하는 경우도 많다.)

---

## 7. LIMIT 활용 
```sql
ORDER BY created_at DESC
LIMIT 20;
```
필요한 만큼만 읽는다.
페이징에서는 매우 중요하다.

---

## 8. OFFSET 주의 

```sql
LIMIT 100000, 20
```
100000건을 건너뛰고
```
20건을 읽는다.
	↓
매우 느리다.
```
추천
Keyset Pagination
```sql
WHERE id > 100000
LIMIT 20
```

---

## 9. JOIN 최적화 

작은 테이블부터
JOIN하는 것이 일반적으로 유리하다.

또한

JOIN 컬럼에는
인덱스가 있어야 한다.

---

## 10. JOIN 컬럼 인덱스 

예)
```
user.id
order.user_id
```
둘 다
인덱스 필요

없으면
Nested Loop Join 비용 증가

---

## 11. 불필요한 DISTINCT 제거 

나쁜 예
```sql
SELECT DISTINCT ...
```
```
중복이 없는데도 사용
	↓
불필요한 정렬 발생
```

---

## 12. ORDER BY 최적화 
```sql
ORDER BY created_at
```
created_at 인덱스가 있으면
Filesort 없이 처리 가능

---

## 13. GROUP BY 최적화 

GROUP BY도
인덱스를 활용할 수 있다.
인덱스가 없으면
Using temporary
Using filesort
발생 가능

---

## 14. 서브쿼리(Subquery) 

상황에 따라
JOIN이 더 빠를 수 있다.

하지만

MySQL 8.0은
서브쿼리 최적화가 많이 개선되었다.

무조건 JOIN이 정답은 아니다.

---

## 15. 함수 사용 최소화 

나쁜 예
```sql
WHERE UPPER(name)='KIM'
	↓
인덱스 활용 어려움
```

좋은 예
```sql
WHERE name='Kim'
```

## 16. COUNT(*) 
```sql
SELECT COUNT(*)
```
가장 권장
```sql
COUNT(id)
```
보다 일반적으로 효율적이며
MySQL에서 최적화가 잘 되어 있다.

## 17. INSERT 여러 건 한 번에 

나쁜 예
```sql

INSERT ...
INSERT ...
```

```sql
INSERT ...

(...),

(...);
```
