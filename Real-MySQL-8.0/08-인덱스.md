## 1. 인덱스(Index) 

가장 중요한 개념
인덱스란
데이터를 빠르게 찾기 위한 자료구조
예)
```
전화번호부
이름 → 페이지
찾기 빠름
```
DB도 동일하다.
인덱스가 없으면
```sql
SELECT *
FROM user
WHERE name='Kim';
```
```
	↓
모든 행 검색
	↓
Full Table Scan
```
인덱스가 있으면
```
B+Tree 탐색
	↓
필요한 데이터만 조회
```

---

## 2. B+Tree

MySQL 인덱스는 대부분
__B+Tree__
구조이다.
```
          [50]

      /          \

   [20]         [80]

  /   \         /   \

10   30      60    90
```
특징
- 정렬되어 있음
- 범위 검색 빠름
- O(logN)

## 4. Clustered Index

InnoDB의 핵심
Primary Key 자체가
데이터 저장 순서이다.
```
PK
	↓
실제 데이터
```
즉
PK 순으로 저장된다.

---

## 5. Secondary Index

보조 인덱스
```
name
	↓
PK 값 저장
```
예)
```
INDEX(name)
```
```
	↓
실제 데이터 위치가 아니라
PK를 저장
	↓
한 번 더 조회
```

---

## 6. 인덱스 조회 과정
```sql
SELECT *
FROM user
WHERE name='Kim'
```
```
	↓
Secondary Index 검색
	↓
PK 획득
	↓
Clustered Index 조회
	↓
데이터 반환
```

## 7. Covering Index 

필요한 컬럼이
모두 인덱스 안에 있다.
```sql
SELECT name
FROM user
WHERE name='Kim'
```
```
name 인덱스만 있으면
	↓
테이블 접근 없음
	↓
매우 빠름
```
예) 
아래의 경우 
```sql
SELECT name, age
FROM member
WHERE name = 'Kim';
```
복합인덱스(커버링 가능)
```sql
INDEX(name, age)
```
단일인덱스(커버링 불가)
```sql
INDEX(name)
INDEX(age)
```

## 10. 복합 인덱스(Composite Index)

실무에서 가장 많이 사용
```sql
INDEX(name, age)
```
순서가 중요

### Left-Most Prefix Rule 
```sql
INDEX(name, age)
```
가능
```sql
WHERE name=?
```
가능
```sql
WHERE name=? AND age=?
```
불가능
```sql
WHERE age=?
```
맨 앞 컬럼(name)이 없어서
인덱스를 제대로 활용하기 어렵다.

---

## 11. Index Scan 종류 
### Index Range Scan

가장 좋은 방식
```sql
WHERE age > 20
```
필요한 부분만 읽음

### Index Full Scan

인덱스 전체 탐색
Table Scan보단 낫다.

### Index Skip Scan

8.0 추가
첫 컬럼 없이도
일부 상황에서
인덱스 사용 가능
하지만
Left-Most Rule이
여전히 중요하다.

## 12. 인덱스를 못 타는 경우 

가장 많이 하는 실수

나쁜 예 (함수 사용)
```sql
WHERE YEAR(created_at)=2025
```


나쁜 예
```sql
WHERE created_at >= '2025-01-01'
LIKE '%kim%'
LIKE '%kim'
```
좋은 예
```sql
LIKE 'kim%'
```

연산 (컬럼 자체를 변형하면 안 된다.)
```sql
WHERE salary+100=1000
```
