## 1. 프로토콜
네트워크에서 통신할 때의 규약을 프로토콜이라는 용어를 사용한다. 

- 물리적 측면 : 이더넷
- 논리적 측면 : TCP/IP

과거 매우 느린 네트워크에서 최대한 효율적으로 통신하는 것이 목표이다 보니 대부분의 프로토콜이 문자 기반이 아닌 __2진수 비트(bit)__ 기반으로 만들어졌다.

그러나, 애플리케이션 레벨에서는 __문자 기반__ 프로토콜을 많이 사용하고있다. 대표적인게 HTTP와 SMTP다.

HTTP 프로토콜 헤더
```
GET /api HTTP/1.1
Accept: text/html, application/xhtml+xml, */*
...
```

## 2. OSI 7계층
네트워크를 역할별로 나눠놓은 모델이다.

| 계층 | 이름 | 대표 장비 / 핵심 개념 |
|:---:|---|---|
| **7** | 응용 계층 (Application) | HTTP, HTTPS, DNS, SMTP, SSH |
| **6** | 표현 계층 (Presentation) | 인코딩, 암호화, 압축 |
| **5** | 세션 계층 (Session) | 세션 연결, 유지, 종료 |
| **4** | 전송 계층 (Transport) | TCP, UDP, Port |
| **3** | 네트워크 계층 (Network) | 라우터, IP 주소 |
| **2** | 데이터링크 계층 (Data Link) | 스위치, MAC 주소, Ethernet |
| **1** | 물리 계층 (Physical) | 허브, 케이블, 전기·광 신호 |

1~4계층 : 데이터 플로 계층 / 하위 계층
5~7계층 : 애플리케이션 계층 / 상위 계층

## 3. TCP/IP 모델
TCP/IP는 TCP와 IP라는 프로토콜 두 개만 의미하는 게 아니다.

```
TCP/IP

Application
 └ HTTP, DNS, SMTP, SSH ...

Transport
 └ TCP, UDP

Internet
 └ IP, ICMP ...

Network Access
 └ Ethernet, Wi-Fi ...
```

넓은 의미로는 인터넷 통신에 사용하는 프로토콜 체계 전체를 TCP/IP라고 부른다.

## 5. 캡슐화/디캡슐화

HTTP 요청을 보냈을때
각 계층이 자기에게 필요한 정보를 붙이는 것을 __캡슐화__ 라고한다.
```
HTTP 데이터
```
TCP가 자기 정보를 붙인다.
```
[TCP 헤더][HTTP 데이터]
```
IP가 또 붙인다.
```
[IP 헤더][TCP 헤더][HTTP 데이터]
```
Ethernet이 또 붙인다.
```
[Ethernet 헤더][IP 헤더][TCP 헤더][HTTP 데이터]
```

반대로 서버에서 하나씩 열어보는 과정을 __디캡슐화__ 라고한다.

```
Ethernet 제거
 ↓
IP 제거
 ↓
TCP 제거
 ↓
HTTP 데이터
```

        ↓
